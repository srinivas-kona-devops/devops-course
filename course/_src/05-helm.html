2. Install and use a public chart

bash
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
helm version --short
helm repo add bitnami https://charts.bitnami.com/bitnami && helm repo update
helm search repo nginx | head -5
helm show values bitnami/nginx | head -40
helm install demo bitnami/nginx -n helm-lab --create-namespace --set service.type=ClusterIP --set replicaCount=2
helm list -A; helm status demo -n helm-lab
helm get values demo -n helm-lab; helm get manifest demo -n helm-lab | head -20

3. Upgrade, history, rollback

bash
helm upgrade demo bitnami/nginx -n helm-lab --set service.type=ClusterIP --set replicaCount=3 --atomic --timeout 3m
helm history demo -n helm-lab
helm rollback demo 1 -n helm-lab --wait
helm uninstall demo -n helm-lab
Production flags
--atomic rolls back automatically on failure, --wait blocks until pods are ready, -f values-prod.yaml keeps settings in Git, helm diff upgrade (plugin) previews changes.

4. Write your own chart

bash
cd ~/lab && helm create myapp && tree myapp
cat > myapp/values.yaml <<'EOT'
replicaCount: 2
image:
  repository: nginxinc/nginx-unprivileged
  tag: "1.27-alpine"
  pullPolicy: IfNotPresent
service: {type: ClusterIP, port: 80, targetPort: 8080}
resources:
  requests: {cpu: 50m, memory: 64Mi}
  limits: {cpu: 200m, memory: 128Mi}
config: {greeting: hello}
EOT
cat > myapp/templates/deployment.yaml <<'EOT'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.fullname" . }}
  labels: {{- include "myapp.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels: {{- include "myapp.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels: {{- include "myapp.selectorLabels" . | nindent 8 }}
      annotations:
        checksum/config: {{ toYaml .Values.config | sha256sum }}
    spec:
      containers:
      - name: app
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports: [{containerPort: {{ .Values.service.targetPort }}}]
        env:
        - {name: GREETING, value: {{ .Values.config.greeting | quote }}}
        resources: {{- toYaml .Values.resources | nindent 10 }}
EOT
rm -f myapp/templates/{hpa,ingress,serviceaccount}.yaml myapp/templates/tests/*
cat > myapp/templates/service.yaml <<'EOT'
apiVersion: v1
kind: Service
metadata:
  name: {{ include "myapp.fullname" . }}
spec:
  type: {{ .Values.service.type }}
  selector: {{- include "myapp.selectorLabels" . | nindent 4 }}
  ports: [{port: {{ .Values.service.port }}, targetPort: {{ .Values.service.targetPort }}}]
EOT
helm lint myapp
helm template rel myapp | head -40
helm install rel myapp -n helm-lab --create-namespace --dry-run --debug | tail -5
helm install rel myapp -n helm-lab --wait
helm upgrade rel myapp -n helm-lab --set config.greeting=namaste --wait
kubectl -n helm-lab exec deploy/rel-myapp -- printenv GREETING
Why the checksum annotation
Pods do not restart when a ConfigMap changes. Putting a hash of the config in the pod template forces a rolling restart on helm upgrade.

Template syntax cheat sheet

SyntaxMeaning
{{ .Values.x }}Value from values.yaml or --set
{{ .Release.Name }}Release name, also .Release.Namespace
{{ include "name" . | nindent 4 }}Reuse a named helper, indent on a new line
{{- if .Values.enabled }} ... {{- end }}Conditional block, - trims whitespace
{{ default "x" .Values.y }}, quote, toYamlCommon functions

6. Hooks and tests

bash
cat > ~/lab/myapp/templates/test.yaml <<'EOT'
apiVersion: v1
kind: Pod
metadata:
  name: {{ include "myapp.fullname" . }}-test
  annotations: {"helm.sh/hook": test}
spec:
  restartPolicy: Never
  containers:
  - {name: curl, image: "curlimages/curl:8.10.1", command: ["curl","-sf","http://{{ include "myapp.fullname" . }}:{{ .Values.service.port }}"]}
EOT
helm upgrade rel ~/lab/myapp -n helm-lab --wait
helm test rel -n helm-lab
helm uninstall rel -n helm-lab; kubectl delete ns helm-lab
Checkpoint
helm lint passes, an upgrade changes the running environment variable, and helm rollback restores the previous revision.
