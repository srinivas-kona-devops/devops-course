GitHub ActionsArgo CD~90 min
Lab goal
Automate the path from commit to cluster: test, build, push an image without stored AWS keys, update a config repository, and let Argo CD apply it.

1. Anatomy of a workflow

TermMeaning
WorkflowA YAML file in .github/workflows/
Event (on)What starts it: push, pull_request, schedule, workflow_dispatch, release
JobA set of steps on one runner; jobs run in parallel unless linked by needs
StepA shell command (run) or a reusable action (uses)
RunnerThe machine: GitHub-hosted (ubuntu-24.04) or your own self-hosted
EnvironmentNamed target (dev, prod) with approvals and its own secrets

2. First CI workflow

yaml
mkdir -p .github/workflows
cat > .github/workflows/ci.yml <<'EOT'
name: ci
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  test:
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    strategy:
      matrix:
        python: ["3.11", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python }}
          cache: pip
      - run: pip install -r api/requirements.txt
      - run: python -m py_compile api/app.py
  chart:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: azure/setup-helm@v4
      - run: helm lint chart --set db.password=x
EOT
Least privilege by default
Set permissions: contents: read at the top and grant more only to the job that needs it. Pin third-party actions to a full commit SHA in production, because tags can be moved.

2a. Anatomy of a workflow run

A pull request runs test and chart in parallel. A merge to main adds the image build and the deploy stages in the next sections.

3. No stored AWS keys (OIDC)

Long-lived access keys in repository secrets are a common cause of cloud breaches. With OpenID Connect, each job requests a short-lived token and AWS exchanges it for temporary credentials.

bash
ACCT=$(aws sts get-caller-identity --query Account --output text)
aws iam create-open-id-connect-provider --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com    # skip if your account already has it
cat > /tmp/gha-trust.json <<EOT
{"Version":"2012-10-17","Statement":[{
  "Effect":"Allow",
  "Principal":{"Federated":"arn:aws:iam::${ACCT}:oidc-provider/token.actions.githubusercontent.com"},
  "Action":"sts:AssumeRoleWithWebIdentity",
  "Condition":{
    "StringEquals":{"token.actions.githubusercontent.com:aud":"sts.amazonaws.com"},
    "StringLike":{"token.actions.githubusercontent.com:sub":"repo:YOUR_ORG/YOUR_REPO:ref:refs/heads/main"}}}]}
EOT
aws iam create-role --role-name gha-ecr-push --assume-role-policy-document file:///tmp/gha-trust.json
aws iam attach-role-policy --role-name gha-ecr-push --policy-arn arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryPowerUser
Security: scope the subject claim
The sub condition is what stops other repositories from assuming your role. Always restrict it to your repository and branch or environment. PowerUser on ECR is broad for a lab; write a policy limited to one repository for real use.

4. Build and push the image

yaml
cat > .github/workflows/release.yml <<'EOT'
name: release
on:
  push:
    branches: [main]
    paths: ["api/**"]
permissions:
  id-token: write      # required for OIDC
  contents: read
env:
  AWS_REGION: ap-south-1
  REPO: todo-api
jobs:
  image:
    runs-on: ubuntu-24.04
    outputs:
      tag: ${{ steps.meta.outputs.tag }}
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_ACCOUNT_ID }}:role/gha-ecr-push
          aws-region: ${{ env.AWS_REGION }}
      - id: ecr
        uses: aws-actions/amazon-ecr-login@v2
      - id: meta
        run: echo "tag=${GITHUB_SHA::8}" >> "$GITHUB_OUTPUT"
      - uses: docker/setup-buildx-action@v3
      - uses: docker/build-push-action@v6
        with:
          context: api
          push: true
          tags: ${{ steps.ecr.outputs.registry }}/${{ env.REPO }}:${{ steps.meta.outputs.tag }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
EOT

Store the account ID as a repository variable (vars.AWS_ACCOUNT_ID); it is an identifier, not a secret.

5. Environments, approvals, reusable workflows

yaml
cat > .github/workflows/deploy.yml <<'EOT'
name: deploy
on:
  workflow_call:
    inputs:
      env: {type: string, required: true}
      tag: {type: string, required: true}
jobs:
  bump:
    runs-on: ubuntu-24.04
    environment: ${{ inputs.env }}      # prod can require reviewers in repository settings
    steps:
      - uses: actions/checkout@v4
        with:
          repository: YOUR_ORG/todo-config
          token: ${{ secrets.CONFIG_REPO_TOKEN }}
      - run: |
          sed -i "s|^\(\s*tag:\).*|\1 \"${{ inputs.tag }}\"|" envs/${{ inputs.env }}/values.yaml
          git config user.name "ci-bot" && git config user.email "ci-bot@users.noreply.github.com"
          git commit -am "deploy ${{ inputs.env }}: ${{ inputs.tag }}" && git push
EOT
# call it from release.yml, after the image job:
#   deploy-dev:  {needs: image, uses: ./.github/workflows/deploy.yml, with: {env: dev,  tag: "${{ needs.image.outputs.tag }}"}, secrets: inherit}
#   deploy-prod: {needs: deploy-dev, uses: ./.github/workflows/deploy.yml, with: {env: prod, tag: "${{ needs.image.outputs.tag }}"}, secrets: inherit}
Why a separate config repository
Keeping manifests apart from application code means a deploy is a small, reviewable commit, and the app pipeline never needs cluster credentials.

6. GitOps with Argo CD

bash
kubectl create namespace argocd
kubectl apply -n argocd --server-side -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl -n argocd rollout status deploy/argocd-server
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d; echo
kubectl -n argocd port-forward svc/argocd-server 8443:443 &      # https://localhost:8443, user admin
cat > app.yaml <<'EOT'
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata: {name: todo-dev, namespace: argocd}
spec:
  project: default
  source:
    repoURL: https://github.com/YOUR_ORG/todo-config.git
    targetRevision: main
    path: envs/dev
  destination: {server: https://kubernetes.default.svc, namespace: todo-dev}
  syncPolicy:
    automated: {prune: true, selfHeal: true}
    syncOptions: [CreateNamespace=true]
EOT
kubectl apply -f app.yaml
kubectl -n argocd get applications
# prove self-healing: change something by hand, Argo CD reverts it
kubectl -n todo-dev scale deploy --all --replicas=7; sleep 30; kubectl -n todo-dev get deploy
SettingEffect
prune: trueDelete cluster objects that were removed from Git
selfHeal: trueRevert manual changes to match Git
Disable automated for prodRequire a manual sync button for production

7. Self-hosted runners and local testing

bash
# run workflows locally in Docker (approximate, not identical to GitHub)
curl -s https://raw.githubusercontent.com/nektos/act/master/install.sh | bash -s -- -b /usr/local/bin
act pull_request -j test
# lint workflow files before pushing
docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest
# self-hosted runner: Settings, Actions, Runners, New self-hosted runner shows the exact commands and a one-time token
Security: self-hosted runners
Never attach a self-hosted runner to a public repository: anyone who can open a pull request could run code on it. Use ephemeral runners (for example Actions Runner Controller on Kubernetes) so each job starts clean.

8. Hardening checklist

RiskControl
Stolen cloud keysOIDC with a narrow sub condition
Over-permissive tokenExplicit permissions: per workflow or job
Compromised third-party actionPin to commit SHA, enable Dependabot for actions
Script injectionNever place ${{ github.event.* }} text directly inside run:; pass it through env:
Accidental production deployEnvironment with required reviewers and branch rules
Forked pull requestsSecrets are not exposed to forks; avoid pull_request_target with untrusted code
Checkpoint
A pull request runs tests in a matrix, a merge builds and pushes an image using OIDC, a config commit follows, and Argo CD applies it and reverts a manual scale.
