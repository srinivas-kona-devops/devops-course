2. Install with Docker

bash
mkdir -p ~/lab/jenkins && cd ~/lab/jenkins
cat > Dockerfile <<'EOT'
FROM jenkins/jenkins:lts-jdk17
USER root
RUN apt-get update && apt-get install -y docker.io && rm -rf /var/lib/apt/lists/* && usermod -aG docker jenkins
USER jenkins
RUN jenkins-plugin-cli --plugins workflow-aggregator git configuration-as-code credentials-binding docker-workflow blueocean
EOT
cat > compose.yaml <<'EOT'
services:
  jenkins:
    build: .
    user: root
    ports: ["8088:8080", "50000:50000"]
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
volumes: {jenkins_home: {}}
EOT
docker compose up -d --build
docker compose logs -f jenkins 2>&1 | grep -m1 -A2 "initialAdminPassword"
docker compose exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
Lab shortcut
Mounting the Docker socket and running as root gives Jenkins full control of the host. That is acceptable for a throwaway lab. In production use separate agents (Kubernetes pod agents or ephemeral VMs) and rootless builders such as Kaniko or BuildKit.

Open http://SERVER_IP:8088, paste the password, install suggested plugins, create the admin user.

3. Your first Pipeline (Jenkinsfile)

groovy
pipeline {
  agent any
  options { timestamps(); timeout(time: 20, unit: 'MINUTES'); buildDiscarder(logRotator(numToKeepStr: '15')) }
  environment { IMAGE = "localhost:5000/hello" ; TAG = "${env.BUILD_NUMBER}" }
  stages {
    stage('Checkout') { steps { checkout scm } }
    stage('Test')     { steps { sh 'python3 -m py_compile app.py' } }
    stage('Build')    { steps { sh 'docker build -t $IMAGE:$TAG .' } }
    stage('Push')     { steps { sh 'docker push $IMAGE:$TAG' } }
    stage('Deploy')   {
      when { branch 'main' }
      steps { sh 'kubectl set image deploy/hello hello=$IMAGE:$TAG -n apps' }
    }
  }
  post {
    success { echo 'Pipeline succeeded' }
    failure { echo 'Pipeline failed' }
    always  { cleanWs() }
  }
}

Create a Multibranch Pipeline job pointing at your repository. Jenkins finds the Jenkinsfile on every branch and builds each one.

4. Credentials, parameters, parallel, approvals

groovy
pipeline {
  agent any
  parameters { choice(name: 'ENV', choices: ['dev', 'staging', 'prod'], description: 'Target') }
  stages {
    stage('Checks in parallel') {
      parallel {
        stage('Lint')     { steps { sh 'echo lint' } }
        stage('Unit')     { steps { sh 'echo unit tests' } }
        stage('Security') { steps { sh 'echo image scan' } }
      }
    }
    stage('Approve prod') {
      when { expression { params.ENV == 'prod' } }
      steps { input message: 'Deploy to production?', ok: 'Deploy' }
    }
    stage('Use a secret') {
      steps {
        withCredentials([string(credentialsId: 'api-token', variable: 'TOKEN')]) {
          sh 'curl -s -H "Authorization: Bearer $TOKEN" https://example.com -o /dev/null -w "%{http_code}\n"'
        }
      }
    }
  }
}
Never echo secrets
Add secrets under Manage Jenkins, Credentials. Reference them only through withCredentials; Jenkins masks the value in logs. Do not put secrets in the Jenkinsfile or in environment as plain text.

5. Dynamic Kubernetes agents

Each build runs in a fresh pod, so there is no agent drift and nothing to patch. Install the Kubernetes plugin and configure the cluster URL and credentials, then:

groovy
pipeline {
  agent {
    kubernetes {
      yaml '''
        apiVersion: v1
        kind: Pod
        spec:
          containers:
          - {name: tools, image: "alpine/k8s:1.30.4", command: [sleep], args: [infinity]}
          - {name: kaniko, image: "gcr.io/kaniko-project/executor:debug", command: [sleep], args: [infinity]}
      '''
    }
  }
  stages {
    stage('Deploy') { steps { container('tools') { sh 'kubectl version --client; helm version --short' } } }
  }
}

6. Configuration as Code and CLI

yaml
cat > jenkins.yaml <<'EOT'
jenkins:
  systemMessage: "Managed by JCasC"
  numExecutors: 0
  securityRealm:
    local:
      allowsSignup: false
      users: [{id: admin, password: "${ADMIN_PASSWORD}"}]
  authorizationStrategy:
    loggedInUsersCanDoAnything: {allowAnonymousRead: false}
EOT
