2. Install a single-node cluster with kubeadm

Version
Set K8S_MINOR to a current supported minor release from kubernetes.io/releases. The value below is an example, so confirm it before you run the commands.
bash
export K8S_MINOR=v1.33
# 1. container runtime
apt -y install containerd
mkdir -p /etc/containerd && containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
systemctl restart containerd && systemctl enable containerd

# 2. kubeadm, kubelet, kubectl
curl -fsSL https://pkgs.k8s.io/core:/stable:/$K8S_MINOR/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes.gpg] https://pkgs.k8s.io/core:/stable:/$K8S_MINOR/deb/ /" > /etc/apt/sources.list.d/kubernetes.list
apt update && apt -y install kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl

# 3. initialise
kubeadm init --pod-network-cidr=10.244.0.0/16
mkdir -p ~/.kube && cp /etc/kubernetes/admin.conf ~/.kube/config
kubectl taint nodes --all node-role.kubernetes.io/control-plane-   # single node only

# 4. pod network (Flannel matches the CIDR above)
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
kubectl get nodes -w
Faster alternatives
k3s: curl -sfL https://get.k3s.io | sh - (single binary, includes Traefik and local storage). kind: Kubernetes inside Docker, good for CI. Use kubeadm when you want to learn how the cluster is assembled.

4. Pod, Deployment, ReplicaSet

bash
mkdir -p ~/lab
cat > ~/lab/web.yaml <<'EOT'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: lab
  labels: {app: web}
spec:
  replicas: 3
  revisionHistoryLimit: 5
  strategy:
    type: RollingUpdate
    rollingUpdate: {maxSurge: 1, maxUnavailable: 0}
  selector:
    matchLabels: {app: web}
  template:
    metadata:
      labels: {app: web}
    spec:
      securityContext: {runAsNonRoot: true, runAsUser: 101, seccompProfile: {type: RuntimeDefault}}
      containers:
      - name: web
        image: nginxinc/nginx-unprivileged:1.27-alpine
        ports: [{containerPort: 8080}]
        resources:
          requests: {cpu: 50m, memory: 64Mi}
          limits: {cpu: 200m, memory: 128Mi}
        readinessProbe: {httpGet: {path: /, port: 8080}, periodSeconds: 5}
        livenessProbe: {httpGet: {path: /, port: 8080}, initialDelaySeconds: 10, periodSeconds: 10}
        securityContext: {allowPrivilegeEscalation: false, capabilities: {drop: [ALL]}}
EOT
k apply -f ~/lab/web.yaml
k -n lab rollout status deploy/web; k -n lab get deploy,rs,pods -o wide

Rolling update and rollback

bash
k -n lab set image deploy/web web=nginxinc/nginx-unprivileged:1.27.3-alpine
k -n lab rollout status deploy/web
k -n lab rollout history deploy/web
k -n lab rollout undo deploy/web
k -n lab scale deploy/web --replicas=5
k -n lab delete pod -l app=web --wait=false; k -n lab get pods -w   # self-healing

Ingress with ingress-nginx

bash
helm upgrade --install ingress-nginx ingress-nginx --repo https://kubernetes.github.io/ingress-nginx \
  -n ingress-nginx --create-namespace --set controller.service.type=NodePort --set controller.service.nodePorts.http=30080
cat > ~/lab/ing.yaml <<'EOT'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: {name: web, namespace: lab}
spec:
  ingressClassName: nginx
  rules:
  - host: web.lab.local
    http:
      paths:
      - {path: /, pathType: Prefix, backend: {service: {name: web, port: {number: 80}}}}
EOT
k apply -f ~/lab/ing.yaml
curl -s -H 'Host: web.lab.local' http://127.0.0.1:30080 | head -4

Helm is covered in detail on page 5. Ingress-nginx is one of several controllers; the Gateway API (gateway.networking.k8s.io) is the newer, more expressive successor and is used by Istio on page 6.

6. Configuration: ConfigMap and Secret

bash
k -n lab create configmap app-config --from-literal=LOG_LEVEL=info --from-literal=GREETING=hello
k -n lab create secret generic app-secret --from-literal=DB_PASSWORD='S3cret!'
k -n lab get secret app-secret -o jsonpath='{.data.DB_PASSWORD}' | base64 -d; echo
k -n lab set env deploy/web --from=configmap/app-config
k -n lab set env deploy/web --from=secret/app-secret --prefix=SEC_
k -n lab exec deploy/web -- env | grep -E 'LOG_LEVEL|SEC_'
Secrets are encoded, not encrypted
Base64 is not protection. Enable etcd encryption at rest, restrict RBAC on secrets, and use an external manager (AWS Secrets Manager with External Secrets Operator, or Vault) for real systems. Never commit Secret manifests; use Sealed Secrets or SOPS if they must live in Git.

7. Storage

bash
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/master/deploy/local-path-storage.yaml
k patch storageclass local-path -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
cat > ~/lab/db.yaml <<'EOT'
apiVersion: v1
kind: Service
metadata: {name: db, namespace: lab}
spec: {clusterIP: None, selector: {app: db}, ports: [{port: 5432}]}
---
apiVersion: apps/v1
kind: StatefulSet
metadata: {name: db, namespace: lab}
spec:
  serviceName: db
  replicas: 1
  selector: {matchLabels: {app: db}}
  template:
    metadata: {labels: {app: db}}
    spec:
      containers:
      - name: pg
        image: postgres:16-alpine
        env:
        - {name: POSTGRES_PASSWORD, valueFrom: {secretKeyRef: {name: app-secret, key: DB_PASSWORD}}}
        - {name: PGDATA, value: /var/lib/postgresql/data/pgdata}
        volumeMounts: [{name: data, mountPath: /var/lib/postgresql/data}]
  volumeClaimTemplates:
  - metadata: {name: data}
    spec: {accessModes: [ReadWriteOnce], resources: {requests: {storage: 1Gi}}}
EOT
k apply -f ~/lab/db.yaml; k -n lab get sts,pvc,pv
k -n lab exec db-0 -- psql -U postgres -c 'create table t(i int); insert into t values (1);'
k -n lab delete pod db-0; k -n lab wait --for=condition=ready pod/db-0 --timeout=90s
k -n lab exec db-0 -- psql -U postgres -c 'select * from t;'   # data survived

8. Autoscaling and resource governance

bash

apiVersion: v1
kind: ResourceQuota
metadata: {name: lab-quota, namespace: lab}
spec: {hard: {requests.cpu: "2", requests.memory: 2Gi, pods: "30"}}
---
apiVersion: v1
kind: LimitRange
metadata: {name: defaults, namespace: lab}
spec: {limits: [{type: Container, default: {cpu: 200m, memory: 128Mi}, defaultRequest: {cpu: 50m, memory: 64Mi}}]}
EOT
k apply -f ~/lab/quota.yaml; k -n lab describe quota

10. Security: RBAC, NetworkPolicy, Pod Security

bash
k -n lab create serviceaccount reader
k -n lab create role pod-reader --verb=get,list,watch --resource=pods
k -n lab create rolebinding reader-bind --role=pod-reader --serviceaccount=lab:reader
k auth can-i list pods -n lab --as=system:serviceaccount:lab:reader      # yes
k auth can-i delete pods -n lab --as=system:serviceaccount:lab:reader    # no
k label namespace lab pod-security.kubernetes.io/enforce=baseline pod-security.kubernetes.io/warn=restricted
cat > ~/lab/netpol.yaml <<'EOT'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: db-from-web-only, namespace: lab}
spec:
  podSelector: {matchLabels: {app: db}}
  policyTypes: [Ingress]
  ingress:
  - from: [{podSelector: {matchLabels: {app: web}}}]
    ports: [{port: 5432}]
EOT
k apply -f ~/lab/netpol.yaml
CNI support
NetworkPolicy is enforced only by CNIs that implement it (Calico, Cilium). Flannel from step 2 accepts the object but does not enforce it. Install Calico or Cilium instead if you want to test enforcement.

11. Customize manifests with Kustomize

Kustomize is built into kubectl (k apply -k). It layers environment-specific patches over a shared base without templates.

bash
mkdir -p ~/lab/kz/base ~/lab/kz/overlays/dev ~/lab/kz/overlays/prod
cd ~/lab/kz
cat > base/deploy.yaml <<'EOT'
apiVersion: apps/v1
kind: Deployment
metadata: {name: web}
spec:
  replicas: 1
  selector: {matchLabels: {app: web}}
  template:
    metadata: {labels: {app: web}}
    spec:
      containers:
      - {name: web, image: nginxinc/nginx-unprivileged:1.27-alpine, ports: [{containerPort: 8080}]}
EOT
printf 'resources:\n- deploy.yaml\n' > base/kustomization.yaml
cat > overlays/dev/kustomization.yaml <<'EOT'
resources: [../../base]
namespace: dev
namePrefix: dev-
EOT
cat > overlays/prod/kustomization.yaml <<'EOT'
resources: [../../base]
namespace: prod
namePrefix: prod-
replicas: [{name: web, count: 4}]
images: [{name: nginxinc/nginx-unprivileged, newTag: 1.27.3-alpine}]
labels: [{pairs: {env: prod}, includeSelectors: false}]
EOT
k kustomize overlays/prod | head -30
k create ns dev; k create ns prod
k apply -k overlays/dev; k apply -k overlays/prod
k get deploy -n dev; k get deploy -n prod

12. Node maintenance (drain and uncordon)

bash
NODE=$(k get nodes -o name | head -1)
k cordon $NODE
k drain $NODE --ignore-daemonsets --delete-emptydir-data --timeout=120s
# ... perform maintenance ...
k uncordon $NODE
k get nodes   # confirm STATUS is Ready and not SchedulingDisabled
Always verify
After maintenance, confirm the node is no longer SchedulingDisabled. On managed platforms (for example Gardener-managed Kyma), reconciliation can change cordon state, so check again rather than assuming.
